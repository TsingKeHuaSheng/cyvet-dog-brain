## 二、两个域的对照

| 项目 | 域 0 · 导航侧 | 域 42 · SDK 侧 |
|---|---|---|
| 用途 | 定位、画线、规划、跟踪 | 对接机器狗运控 |
| 端口段（`7400 + 250×域号`） | 7400–7649 | 17900–18149 |
| `RMW_IMPLEMENTATION` | 空（系统默认，FastDDS） | `rmw_cyclonedds_cpp` |
| `CYCLONEDDS_URI` | 不设 | 设，含 `Interfaces=wlP1p1s0` + `Peers=192.168.100.114` |
| 关键话题 | `/cmd_vel`、`/line_route/*`、TF | `/motion/*`、`/motion/status` |
| 环境入口 | `source ~/ws_route/install/setup.bash` + `export ROS_DOMAIN_ID=0` | `source ~/robot_tools/uniubi_motion/dog_env.bash` |
| 跨域桥 | `uniubi-cmd-vel-link`（把域 0 的 `/cmd_vel` 转发到域 42） | 同左 |

> **重点：两个域互相完全不可见。** 在域 0 的终端里 `ros2 service list` 永远看不到 `/motion/*`，反之亦然。这不是故障。

## 四、四条数据流

### 4.1 定位流

```text
雷达点云 ──► FAST-LIO2（局部里程计 lidar→body）
                    │
                    ▼
            Localizer（ICP，算出 map→lidar 校正）
                    │
                    ▼
            TF 树：map → lidar → body → base_link
```

机身位姿查询：

```bash
ros2 run tf2_ros tf2_echo map base_link
```

### 4.2 画线流

```text
鼠标（Draw Route）──► /line_route/stroke（黄线，实时预览）
                    └► /line_route/drawn ──► editor.py ──► hand_drawn.json
                                                        │
                                                        ▼
                                              route_map.py 加密（≤5 cm 间距）
                                                        │
                                                        ▼
                                              /line_route/saved（紫线）
```

### 4.3 跟踪流

```text
walk.py 读 hand_drawn.json
   └► 发 nav2_msgs/action/FollowPath 到 /line_route/follow_path
          └► controller_server（RPP）算速度 ──► /line_route/tracking
                 └► collision_monitor 检查 ──► /line_route/checked
                        └► walk.py 限幅后 ──► /cmd_vel（域 0）
```

### 4.4 速度流（跨域）

```text
/cmd_vel（域 0）
   └► uniubi-cmd-vel-link（domain_bridge）
          └► /cmd_vel（域 42）
                 └► uniubi-motion-bridge：setActionParams()
                        └► DDS 单播 ──► 狗 robotServer ──► 四条腿
```

速度字段映射：

| ROS 字段 | SDK 字段 | 单位 | 符号 |
|---|---|---|---|
| `linear.x` | `lineVelocityX` | m/s | 正 = 前 |
| `linear.y` | `lineVelocityY` | m/s | 正 = 左 |
| `angular.z` | `velocity` | rad/s | 正 = 左转 |

## 五、怎么判断"我站在哪个域"

在每个终端开好后先跑这四条：

```bash
echo "DOMAIN=${ROS_DOMAIN_ID:-0}"
echo "RMW=$RMW_IMPLEMENTATION"
echo "LOCALHOST_ONLY=$ROS_LOCALHOST_ONLY"
echo "CYCLONE=$CYCLONEDDS_URI"
```

| 输出 | 说明 |
|---|---|
| `DOMAIN=0`、其余空 | 域 0，看得到导航那套 |
| `DOMAIN=42`、`RMW=rmw_cyclonedds_cpp`、`CYCLONE=<CycloneDDS>...` | 域 42，看得到 `/motion/*` |

> `DOMAIN=` 空字符串等价于域 0。用 `${ROS_DOMAIN_ID:-0}` 显示，能区分"没设"和"设成 0"。

### 让两个终端输出不同的四个维度

| 维度 | 不同会怎样 |
|---|---|
| `ROS_DOMAIN_ID` | 不同域 → 完全互不可见 |
| `RMW_IMPLEMENTATION` | 不同中间件 → 同域也互不可见 |
| `CYCLONEDDS_URI` | 同域，但限定网卡/peers → 跨机器可能只见一部分 |
| `ROS_LOCALHOST_ONLY` | `=1` 时只看本机 |

四项一致，看到的就必定一致。

## 六、症状 → 落在哪一层

| 症状 | 大概率位置 | 先查 |
|---|---|---|
| `ros2 service list` 看不到 `/motion/*` | 站错域 | `echo $ROS_DOMAIN_ID`，应在 42 |
| 看不到 nav2 / localizer | 站错域或没 source `ws_route` | 应为域 0 + source 过 `ws_route` |
| 能收话题、RPC 全超时 | DDS 单播/回程地址 | `dog_env.bash` 里的 `Interfaces` + `Peers` |
| `discover-only` 找不到狗 | 发现层 | Peers 里的 IP 是否等于狗当前 IP |
| 服务看得见、调用超时 | bridge 没连上狗 | `systemctl --user status uniubi-motion-bridge` |
| `/cmd_vel` 有速度但狗不动 | 跨域转发或控制权 | 域 42 看 `/motion/status.control_state` 是否 = 2 |
| 反复 `front_stop` 停车 | 安全机制正常工作 | 看 `collision_monitor` 与实时点云 |

## 七、关键环境文件

```bash
# 域 42 的完整环境（换 IP / 换狗要改这里）
```

`dog_env.bash` 关键内容：

```bash

export CYCLONEDDS_URI='<CycloneDDS><Domain Id="any"><General><Interfaces><NetworkInterface name="wlP1p1s0"/></Interfaces><AllowMulticast>true</AllowMulticast></General><Discovery><Peers><Peer address="192.168.100.114"/></Peers><ParticipantIndex>auto</ParticipantIndex></Discovery></Domain></CycloneDDS>'
```

**两个必须记住的修改点：**

| 变的什么 | 改哪里 |
|---|---|
| 狗换了 IP | `dog_env.bash` 里的 `<Peer address="..."/>` |
| 换了一台狗 | `motion_bridge.yaml` 里的 `device_id`（= SN） |

改完都要：

```bash
systemctl --user restart uniubi-motion-bridge
```

## 九、一句话总结

> **膜层关系：ROS 2 是接口层，DDS 是传输层，单播/多播只是 DDS 内部的走法。**
> **域号 = 端口段 = 一张独立的网络；两个域互相看不见。**
> **多播负责"认识彼此"，单播负责"说话"；回程地址学错了，就只能听见、不能指挥。**
