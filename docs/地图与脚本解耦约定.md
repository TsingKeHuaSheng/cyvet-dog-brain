# 地图与脚本解耦约定

> 一句话：**地图名只出现在一个地方**（`dogroute use` 写的状态文件），
> 所有 bash / Python / launch 文件都去问它，而不是各自写死 `office4`。

---

## 1. 为什么要有这份约定

以前换场地，要改 `locate_at_start.bash` 里的 `office4`、改 `walk.bash` 的默认值、
还要记得给 `systemd-run` 传环境变量；漏一处就会出现"用新图定位、却用旧图循线"这种
最难查的故障。现在改成：**加一个功能 = 照模板写 6 行，不需要知道当前是哪张图。**

---

## 2. 唯一事实来源

三处按优先级，**只在这一个文件里实现**：`ws_route/src/office4_route/scripts/map_site.py`

| 优先级 | 来源 | 谁写它 |
|---|---|---|
| 1 | 环境变量 `DOG_ROUTE_MAP` | `dogroute` 启动服务、`dogroute walk`、手动 `eval "$(dogroute env)"` |
| 2 | `~/.config/dogroute/selected-map` | `dogroute use <名字>`（跨终端、跨重启保留） |
| 3 | 兜底 `office4`（仅当该目录存在） | 只在"从没选过"的老机器上生效，同时打提示 |

三处都拿不到 → **直接报错并告诉你执行 `dogroute use`**，不会再默默用错地图。

---

## 3. 变量契约

任何脚本 source 了 `~/robot_tools/lib/dog_map.bash` 之后就拿到这些（已 export，子进程可见）：

| 变量 | 值 | 用途 |
|---|---|---|
| `DOG_ROUTE_MAP` | `office4` / `plaza01` … | 地图名，写日志、比对服务 |
| `DOG_MAP_DIR` | `~/robot_ws/maps/<名字>` | 该图的数据根目录 |
| `DOG_MAP_PCD` | `<dir>/map.pcd` | 三维定位底图 |
| `DOG_MAP_GRID` | `<dir>/nav2/map.yaml` | 二维栅格（画线底图） |
| `DOG_ROUTE_JSON` | `<dir>/routes/hand_drawn.json` | 手绘路线 |
| `DOG_LEGACY_MAP` | `office4` | 只用于识别"改版前启动、没记录地图"的老服务 |

一张地图的目录长这样（换图 = 换目录，脚本不动）：

```text
~/robot_ws/maps/<地图名>/
├── map.pcd                  三维定位底图（FAST-LIO2 用）
├── poses.txt                关键帧位姿
├── patches/                 子图
├── nav2/map.yaml|map.pgm    二维栅格（画线底图，dogroute grid 生成）
├── routes/hand_drawn.json   手绘路线（含地图名 + 点云指纹，防串图）
└── navigation_preview/      旧版预览产物（保留兼容）
```

---

## 4. 现在谁在用这个契约

| 脚本 | 用的是 | 换图后 |
|---|---|---|
| `scripts/walk.bash`（循线） | `DOG_ROUTE_JSON` | 自动跟到新图，文件不存在时提示先画线 |
| `scripts/locate_at_start.bash`（自定位） | `DOG_MAP_PCD` | 自动用新图 pcd；并把地图名传给 `office4-localization` 服务 |
| `scripts/start.bash`（画线界面） | `DOG_MAP_GRID` | 自动用新图栅格；并把地图名传给 `office4-route` 服务 |
| `scripts/session_guard.bash`（守卫） | `DOG_ROUTE_MAP` | 服务里的图和当前选择不一致时拒绝执行，并告诉你怎么切 |
| `scripts/stand.bash`（取权 + 零速 Walking） | 不需要地图 | 与地图完全无关 |
| `scripts/dogroute.py` | `map_site` | `status` 显示当前图与文件齐全情况 |
| `config/office4.launch.py` | 环境变量 → 状态文件 | 没有栅格时报错并提示 `dogroute grid`，不再静默无底图 |
| `~/robot_tools/scripts/relocalize_scan.sh` | `DOG_MAP_PCD` | 默认对当前图重定位 |
| `~/robot_tools/navigation_preview/start_preview.sh` | `DOG_MAP_DIR` | 默认预览当前图的栅格 |

> `robot_tools/office4_route/{walk,start,stand,locate_at_start}.bash` 是上面这些脚本的
> **软链接**，改一处两处都生效，不存在两份实现。

## 5. 以后写新功能，照这三个模板

### 5.1 Bash（最常见：一个"做某事"的脚本）

```bash
#!/usr/bin/env bash
set -e
source "$HOME/robot_tools/lib/dog_map.bash"      # ← 唯一需要记住的一行
test -f "$DOG_MAP_PCD" || { echo "$DOG_ROUTE_MAP 缺 map.pcd" >&2; exit 1; }

echo "在 $DOG_ROUTE_MAP 上执行……"
# 下面随便用 $DOG_MAP_DIR / $DOG_MAP_PCD / $DOG_MAP_GRID / $DOG_ROUTE_JSON
```

### 5.2 Python（节点 / 工具脚本）

```python
import sys
sys.path.insert(0, str(__import__('pathlib').Path.home()
                       / 'ws_route/src/office4_route/scripts'))
from map_site import MAP_NAME, MAP_DIR, map_paths      # 已按优先级解析好

directory, pcd, grid, route = map_paths()
print(f'当前地图 {MAP_NAME}，底图 {pcd}')
```

### 5.3 ROS 2 launch

```python
name = os.environ.get('DOG_ROUTE_MAP') or _saved_map_name()   # 照抄 office4.launch.py
```

要点：**launch 文件里不要出现具体地图名**；需要数据时一律拼 `Path.home()/"robot_ws/maps"/name`。

## 6. 换一张新地图（完整流程，脚本一律不动）

```bash
dogroute use plaza01      # ① 选名（此后所有脚本都跟着它）
dogroute mapping          # ② 遥控走一圈建图
dogroute save             # ③ 保存
dogroute grid             # ④ 生成二维栅格（画线底图）
dogroute locate           # ⑤ 回到起点、原朝向，重定位
dogroute draw             # ⑥ 打开画线窗口（底图 = plaza01）
dogroute stand            # ⑦ 取权 + 零速 Walking
# ⑧ 在 RViz 里画线，松手保存
dogroute walk             # ⑨ 循线
dogroute release          # ⑩ 收工交还控制权
dogroute stop             # ⑪ 关掉画线与定位
```

`dogroute status` 随时查看：当前图、文件齐不齐、三个服务各自在跑哪张图。

临时在某个终端里用另一张图（不改全局选择）：

```bash
# 注意：dogroute 启动器会清掉 DOG_ROUTE_MAP（保证 use 的选择说了算），
# 所以临时切图要直接问 map_site，不要走 dogroute
eval "$(/usr/bin/python3 ~/ws_route/src/office4_route/scripts/map_site.py --shell --map plaza01)"
~/robot_tools/office4_route/walk.bash
```

## 7. 兼容与边界

| 事项 | 说明 |
|---|---|
| 服务名 `office4-route` / `office4-localization` | 历史命名，**与地图名无关**，是"循线窗口"和"定位窗口"的单例服务 |
| ROS 包名 `office4_route` | 同上，历史命名；地图名只存在于数据目录和状态文件 |
| 改版前启动的服务 | 没有记录地图 → 守卫按 `office4` 处理并提示；`dogroute stop` 后用 `locate`/`draw` 重开即可带上地图 |
| 直接执行旧入口 `~/robot_tools/office4_route/start.bash` | 仍可用，会自动取当前图；该图还没栅格时会提示先 `dogroute grid` |
| `~/robot_tools/office4_drive/`（另一条独立链路） | 与地图无关，未纳入本约定 |
| `~/nav2_nav/`（早期 Nav2 试验） | 仍写死 `run3` 默认值，属于实验分支，未纳入；用 ws_route 那套即可 |

## 8. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `还没有选择地图：先执行 dogroute use` | 状态文件不存在，也没有 `office4` 目录 | `dogroute use <名字>` |
| `X 正在使用 office4，而当前选择是 Y` | 上一场地的服务还开着 | `dogroute stop` 再重开，或 `dogroute use office4` 切回去 |
| `还没有为 X 画线` | 该图 `routes/hand_drawn.json` 缺失 | `dogroute draw` 画一条 |
| `X 还没有 map.pcd` | 建图未保存 | `dogroute mapping` → `dogroute save` |
| `X 还没有二维栅格` | 没跑 `grid` | `dogroute grid` |
| `地图名使用 1～64 个字母…` | 状态文件被写脏 | 删除 `~/.config/dogroute/selected-map` 后重新 `dogroute use` |
| 狗走到一半停 | 与本约定无关：碰撞守卫 / 定位丢失 / 电量 | 看 `walk.py` 日志与 `/motion/status` |
