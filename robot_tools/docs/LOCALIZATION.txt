========================================================
  地图定位（Relocalization）操作清单
  机器狗二次开发 · Jetson Orin Nano
  更新日期：2026-11-16
========================================================

【这一步在干什么】

  建图之后，你有一张地图（run1/map.pcd）。
  定位 = 让机器人对照这张地图，算出"我现在在图的哪个位置"。

  输出：map → body 的坐标变换（TF）
  有了它，Nav2 才知道起点在哪，才能规划路径。

【前提条件】

  1. 已有建好的地图：~/robot_ws/maps/run1/map.pcd
  2. 雷达已上电，驱动在跑（由 systemd 自动管理）
  3. 必须先退出建图程序（pgo_launch.py），
     否则两个 lio_node 抢同一个话题
  4. 雷达放在地图原点附近，朝向接近建图起始方向，
     并且保持静止（下面的全零初值只适用于这种情况）

========================================================
 第 0 步：确认建图程序已退出
========================================================

pgrep -af 'lio_node|pgo_node'

# 如果还有残留，清理掉
pkill -f pgo_node
pkill -f lio_node
sleep 2

# 确认雷达驱动还在（这个不要杀）
systemctl status livox-lidar

========================================================
 第 1 步：把雷达放好（很重要）
========================================================

· 放在地图原点附近（建图开始时雷达所在的位置）
· 朝向接近建图开始时的朝向
· 保持静止，不要拿在手上晃动

# 原因：relocalize 的初值给的是全零，含义是
#      "假设你现在就在地图原点、朝向 0 度"。
#      如果实际偏差太大，ICP 匹配会失败。

========================================================
 第 2 步：启动定位组合（终端 1，Jetson 桌面终端）
========================================================

source /opt/ros/humble/setup.bash
source ~/ws_livox/install/setup.bash
source ~/ws_slam/install/setup.bash

ros2 launch localizer localizer_launch.py

# 这条命令会启动三个东西：
#   1. fastlio2/lio_node         实时里程计（定位要用它）
#   2. localizer/localizer_node  重定位（ICP 匹配地图）
#   3. rviz2                     可视化
#
# 【注意】localizer_launch 不启动雷达驱动，
#        驱动由 systemd 的 livox-lidar.service 管。
#        这个终端会打开 RViz，所以要在 Jetson 桌面运行。

========================================================
 第 3 步：加载地图并给初始位姿（终端 2）
========================================================

source /opt/ros/humble/setup.bash
source ~/ws_livox/install/setup.bash
source ~/ws_slam/install/setup.bash

ros2 service call /localizer/relocalize interface/srv/Relocalize \
"{pcd_path: '/home/nvidia/robot_ws/maps/run3/map.pcd',
  x: 0.0, y: 0.0, z: 0.0,
  yaw: 0.0, pitch: 0.0, roll: 0.0}"

# 参数含义：
#   pcd_path       用哪张地图
#   x, y, z        你以为雷达在地图的哪个位置（单位：米）
#   yaw/pitch/roll 你以为的朝向（单位：弧度）
#
# 成功返回：success: true

========================================================
 第 4 步：检查匹配结果
========================================================

# 等几秒让 ICP 收敛，然后执行：
ros2 service call /localizer/relocalize_check \
interface/srv/IsValid "{code: 0}"

# 返回 valid: true  → 定位成功，可以继续
# 返回 valid: false → 没匹配上，见文末「常见问题」

========================================================
 第 5 步：在 RViz 里目视确认
========================================================

# RViz 已经由终端 1 自动打开，检查三件事：

  ① Fixed Frame 选 map

  ② 实时点云（当前扫到的）应该和地图里的墙、墙角重合
     - 完全重合    = 定位正确
     - 整体错开一截 = 位置估计偏了
     - 转了一个角度 = 朝向估计错了

  ③ 缓慢移动雷达，观察画面是否跟着平滑移动
     （这一步是验证「持续跟踪」，不是初次定位）

========================================================
 第 6 步：查看实时位姿
========================================================

ros2 run tf2_ros tf2_echo map body

# 会持续打印 map → body 的变换：
#   translation: x / y / z
#   rotation:    四元数
#
# 静止时这几个数应该基本不动；一直在变说明在漂。

========================================================
 第 7 步：结束
========================================================

· 停止查看位姿：Ctrl+C（终端 3）
· 停止定位：回到终端 1 按 Ctrl+C

========================================================
 两个概念别搞混
========================================================

  relocalize      初次定位：告诉它"你可能在哪"，它去匹配地图
  lio_odom        之后靠 FAST-LIO 的里程计持续跟踪
  tf map→body     两者结合后的最终位姿

  所以：定位只需要做一次（开机时），之后靠里程计自动跟随。

========================================================
 常见问题
========================================================

1. relocalize 返回 success: false
   → 地图路径写错，检查 map.pcd 是否存在
   → 或者 localizer_node 没起来

2. relocalize_check 返回 valid: false
   → 雷达离地图原点太远，或朝向差太多
   → 把雷达放回建图起点附近再试
   → 也可以给一个更接近的估算位姿再调一次

3. RViz 里实时点云和地图整体错开
   → 初值给得不准，重新给一个更接近的 x / y / yaw

4. 报两个 lio_node 冲突
   → 建图程序没退干净，pkill -f lio_node 后再试

5. 完全没有点云
   → 雷达驱动没在跑：systemctl status livox-lidar

6. RViz 打不开（SSH 登录时）
   → 这是正常的，SSH 没有图形界面
   → 定位本身照常工作，换到 Jetson 桌面终端跑就能看到画面
